# Sora-2 Pro Control (Flutter)

Минимальное кроссплатформенное приложение на Flutter для базового взаимодействия с устройством **Sora-2 Pro**. Реализованы панели управления и телеметрии с реальными HTTP-вызовами к контроллеру.

## Основные возможности
- Отображение статуса устройства и его IP-адреса.
- Управление режимами (Auto/Manual/Safe) и командами запуска/остановки.
- Получение телеметрии (температура, заряд батареи, уровень сигнала) с возможностью ручного обновления.
- Структура на Riverpod для удобного расширения и интеграции с реальными сетевыми вызовами.

## Структура проекта
- `lib/main.dart` — точка входа, навигация и основной экран.
- `lib/services/sora_api.dart` — слой работы с API (GET `/status`, `/telemetry`, POST `/commands`).
- `lib/models/device_state.dart` — модели состояния устройства и телеметрии.
- `lib/widgets/` — виджеты панелей управления и телеметрии.

## Настройка и запуск
1. Установите Flutter (3.3+). Например, через `fvm` или официальные инструкции.
2. Задайте параметры доступа к контроллеру Sora-2 Pro (используется Basic Auth и `dart-define`):
   ```bash
   flutter run \
     --dart-define=SORA_BASE_URL=https://<ip или host>/api \
     --dart-define=SORA_USERNAME=<имя_пользователя> \
     --dart-define=SORA_PASSWORD=<пароль>
   ```
   Альтернатива: замените значения по умолчанию в `SoraApiConfig.fromEnvironment()` внутри `lib/services/sora_api.dart`.
3. В корне проекта выполните:
   ```bash
   flutter pub get
   flutter run
   ```
4. Убедитесь, что устройство доступно по сети по указанному `SORA_BASE_URL` и принимает базовую авторизацию.

## Работа с ветками и обновление из `main`
Перед открытием пулл-реквеста обновите вашу рабочую ветку из `main`, чтобы избежать мердж-конфликтов:
```bash
git checkout main
git pull origin main
git checkout work   # или ваша фича-ветка
git rebase main     # либо git merge main
```
Так вы подтянете последние изменения и сможете безопасно отправить PR без лишних конфликтов.
